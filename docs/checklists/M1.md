# M1 in-game check: load, commands, window, settings, languages, `/atw debug`

The offline tests prove that the code agrees with our assumptions about the client; this checklist proves that the
client agrees with the code. It checks the exit criterion of [milestone M1](../roadmap/M1-foundations.md) and it is
**not done yet**: nobody has run the addon on WoW Forever. M1 reads no threat, so nothing here is about threat values
(that is the [M0 probe](../spike/README.md), a separate procedure).

Report the results with the [*In-game test report* form](https://github.com/Finland6738/azeroth-threatwarden/issues/new?template=ingame_test.yml)
(*Check*: for example `M1 step 3.4`) and note them in the table [at the end](#result). One report for everything that
passed is enough; open one per thing that did not.

## What you need

- WoW Forever with at least one character, a second character for step 7, and a weak enemy or a training dummy for the
  combat checks.
- On the PC: Python 3, the repository on an up-to-date `main`, and `tools/local.ini` with your AddOns folder (the file
  the M0 probe uses; copy `tools/local.example.ini` if it is missing). Then, from the repository folder:

```bash
python -I -X utf8 tools/fetch_libs.py
```

```bash
python -I -X utf8 tools/install_addon.py
```

  The first command downloads the libraries; the second copies `AzerothThreatwarden/` into the AddOns folder (run it
  again after every update, then restart the game). The probe `AzTw_Probe` can stay installed.
- Lua errors visible: type `/console scriptErrors 1`, or use an error collector such as BugSack.

`/atw debug` never contains player, guild or realm names, so its text is safe to paste. Replace any name you write
yourself, or that a screenshot shows, with `<player>`.

This checklist describes `v0.1.0`: run it on that release's zip. On `v0.2.0` or later the Monitor tab, the title
bar pill, `/atw demo` and the Settings cards differ ([M2 checklist](M2.md)); skip what it says about them.

## 1. Loading

1. At the character screen, *AddOns* lists **Azeroth Threatwarden** with its logo as the icon; in an Italian client the
   description is in Italian. If it says "out of date", write that down and enable *Load out of date AddOns*.
2. Log in for the first time: **no Lua error**, **no chat message** from the addon, and the window opens by itself in
   the centre, on the **Monitor** tab, with the Nebula theme.
3. `/reload`: again no error and no chat message.

## 2. Commands

Do 2.1–2.5 in one language, then change language (step 5.1) and repeat them.

1. `/atw help` lists, in your own chat window only: `/atw`, then `show`, `hide`, `lock`, `unlock`, `reset`,
   `settings`, `about`, `debug`, `help`, each with a description in the current language.
2. `/atw` hides the window and `/atw` shows it. `/atw hide` and `/atw show` do the same. `/threatwarden` and
   `/threatwarden help` behave like `/atw`. `/atw HELP` (capital letters) works too.
3. `/atw lock` answers "Window locked.", `/atw unlock` "Window unlocked.", `/atw reset` "Window position, size and
   scale reset." and the window is back in the centre.
4. `/atw settings` opens the Settings page, `/atw about` the Info page, `/atw debug` the report box.
5. `/atw demo` answers that it arrives in v0.2.0, `/atw mute` v0.3.0, `/atw reports` v0.4.0;
   `/atw xyz` answers "Unknown command: xyz. Type /atw help."

## 3. The window

1. **Monitor** tab (small): the logo, the title, the state **Off** (hover it: a tooltip explains why), lock and close
   buttons; in the body, a dimmed logo and "Threat monitoring arrives in v0.2.0". There is no *Reports* tab.
2. **Move** it by the title bar; **resize** it from the dashed corner at the bottom right. It stops at a minimum and a
   maximum size and cannot be dragged off the screen. Make it as narrow as possible: the title may disappear, the state
   keeps its word, nothing overlaps.
3. **Settings** tab: the window becomes larger with its top-left corner in the same place, and stays on the screen
   (try it with the small window near the bottom right corner). Resize it too: each tab remembers its own size.
4. **Lock** with the button in the title bar: it cannot be moved or resized and the dashed corner disappears. Unlock.
5. `Esc` closes the window; the next `/atw` opens it. With the window open, opening and closing the game menu works as
   usual.
6. Move it, resize both tabs, lock it, leave the Settings tab selected, then `/reload`: same place, sizes, lock and tab.
7. **Log out** and back in: the same. Close the window and `/reload`: it stays closed.
8. **Close button**: closes the window like `Esc`.
9. `Alt+Z` twice (hide and show the whole interface): the window comes back as it was.

## 4. Minimap button and Addon Compartment

1. A button with the logo is on the minimap. Its tooltip shows the name, "Development build", "Threat monitor: Off" and
   the two clicks.
2. **Left click** shows or hides the window; **right click** opens Settings.
3. Drag it around the minimap, `/reload`: it stays where you left it.
4. In *Settings*, turn *Show minimap button* off: it disappears at once, also after `/reload`. Turn it on again.
5. **Addon Compartment** (the addon list button by the minimap, if your client has it): *Azeroth Threatwarden* is listed
   with the logo, with the same tooltip and the same two clicks. If there is no Compartment, write that down.

## 5. Settings

Open `/atw settings`.

1. **Language**: choose **Italiano**. Nothing changes yet and **Reload now** becomes active; press it. After the reload
   the window, the tooltips, the chat answers and the debug box title are in Italian. Do step 2 in Italian. Then choose
   **English** and reload, then **Automatic**: the language follows the client again, and *Reload now* is active only
   when the choice differs from the language on screen. Try one change with `/reload` typed instead of the button.
2. In both languages, read both pages from top to bottom (mouse wheel): no text is cut, overlapped or shown as a key in
   capitals (such as `SET_THEME`), at the default size and with the window as narrow as it goes.
3. **Theme**: Nebula (dark, violet and orange), Aurora (light, blue and teal), Warden (dark, logo colours). Each one
   applies **at once** to the whole window, the tooltips and the debug box; check that every text stays readable.
4. **Neon effects** off: glows and shadows disappear at once; on: they come back.
5. **Animations** off: changes are immediate; on: short fades and slides.
6. **Font**: choose *Game font*. Note what changes at once. Restart the game: everything uses the game font. Choose
   *Addon font*, restart: Orbitron titles, Outfit text, JetBrains Mono numbers, with no missing or square characters
   (check the Italian accented letters).
7. **Window** card: *Lock the window* matches the title bar button and `/atw lock`, in both directions. Drag the
   **scale** slider: the percentage follows, the window scales (50 %–200 %) only when you release, and stays on the
   screen. *Reset window* puts position, size and scale back and says so.
8. **Reset**: choose another theme and turn effects off, press *Reset settings* once: it asks to click again; wait about
   ten seconds: it goes back to its first label. Click twice: Nebula, effects and animations on, addon font, Automatic
   language, minimap button shown, "Settings reset.".
9. **Game panel**: *Options → AddOns → Azeroth Threatwarden* shows the same pages and they work; a change made there
   shows in the addon window and the other way round. If the entry is missing, empty or broken, write that down with the
   *Settings* section of `/atw debug`.

## 6. Info and credits

1. `/atw about` (or the **Info** pill at the top of Settings): the logo, the name, the version ("Development build"),
   what the addon does, and "Created and designed by Finland. Made with the Italian guild NEBULA.".
2. The **NEBULA logo** next to the credits: the dark one on Nebula and Warden, the light one on Aurora; it changes at
   once with the theme and is sharp, not stretched.
3. Click each link (repository, Ko-fi): the text is selected; `Ctrl+C` and paste it into a browser: the address is
   right. Typing in the box does not change it.
4. The licence (GPL-3.0), the notices and the disclaimer are readable, in both languages.

## 7. Saved data

1. Log in on a **second character**: no error; theme, language and minimap button are the same as on the first
   (account), the window's place, size, lock and tab are its own (character).
2. After a full logout, `AzerothThreatwarden.lua` exists in
   `<WoW folder>/_forever_/WTF/Account/<account>/SavedVariables/` and in the character's `SavedVariables` folder. Do
   not send the files; just say whether they are there.

## 8. In combat

Fight a weak enemy or a training dummy, and while in combat:

1. show, hide (`/atw`, minimap button, `Esc`), move, resize, lock and switch tabs;
2. change theme, scale and minimap button in *Settings*, and open `/atw debug`;
3. press *Reload now* after choosing another language (only if you do not mind reloading mid-fight);
4. no Lua error, no "action blocked" or "interface action failed" message, and your action bars keep working.

## 9. `/atw debug`

1. `/atw debug` opens a box with the report already selected. `Ctrl+C`, paste it into a text editor: the whole text
   comes along. Typing changes nothing; the mouse wheel scrolls; *Select all*, *Close* and `Esc` work.
2. Check, and copy into your result:
   - **header**: `Azeroth Threatwarden diagnostics`, `addon: development copy`;
   - **Client**: `client:` (version and build), `interface: 16001`, `WoW Forever: yes`, `mode: normal`,
     `client language:`, `language: setting …, active …`, `missing language keys: 0`;
   - **Features**: `on: none`;
   - **APIs**: how many are available, missing, restricted and error, and which are not available;
   - **Capabilities** and **Restrictions**: copy them (many capabilities are `unknown` in M1: nothing reads threat yet);
   - **Saved data**: both variables with `current 1` and `schema found 1` (`found none` is right in the session of the very first
     login), no read-only note, `corrupt entries: 0`, `problems corrected at load: none`;
   - **Look**: `repaint failures: 0`, `textures the client refused: 0`, `using the game's font: 0` with *Addon font*;
   - **Settings**: `game settings panel: registered`;
   - **Last errors**: `no addon errors recorded this session`.
3. Check that the report contains no character, guild or realm name.
4. Paste the **whole report** into the *In-game test report* form (field *The /atw debug report*, with the `client:`
   and `locale` information in *Game client*): it is the most useful single thing for the next milestones. Do it once
   out of combat and, if the *Restrictions* section changes, once inside a dungeon.

## 10. UI scales and a custom UI

1. In the game's options turn **UI Scale** on and try the smallest and the largest value: text and icons stay sharp,
   thin lines do not disappear, the window stays on the screen.
2. Set the addon's window scale to 50 % and 200 % (with the largest UI scale too).
3. Change **resolution** or switch between windowed and full screen with the window near the right or bottom edge: it
   comes back inside the screen.
4. If you use a **custom UI** (a replaced minimap, ElvUI-style skins, a minimap button collector): repeat steps 1, 3,
   4 and 5.9 and note which addons are installed. The minimap button must be reachable, or collected by the other addon.
5. Disable the other addons and, if something failed, say whether it still fails alone.

## What to report if something does not work

| Symptom | What to send |
|---|---|
| Lua error at login or on a click | the error text (error frame or BugSack), what you did, `/atw debug` |
| Wrong or missing texture, logo or letter | a screenshot, the theme, `/atw debug` (section *Look*) |
| Text cut or overlapped | a screenshot, language, UI scale, window scale |
| The window or a setting is not remembered | whether you used `/reload`, logout or the game was killed; section *Saved data* |
| No entry in Options → AddOns, or no Compartment entry | section *Settings* and the *APIs* counts of `/atw debug` |
| "Action blocked" or "interface action failed" | the exact message and what you were doing |
